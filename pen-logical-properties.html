Think start / end, not left / right

The same shift flexbox and grid brought: describe layout by the flow of content — inline and block, start and end — not the screen's fixed edges. The reason it matters isn't only right-to-left languages; it's that one set of properties handles English, Arabic, and vertical Japanese, because they respond to both direction and writing-mode. Switch modes and watch which box keeps up.

The common swaps

margin-left / margin-right→margin-inline-start / -end
padding-top / padding-bottom→padding-block-start / -end
top / bottom / left / right→inset-block-* / inset-inline-*
border-left→border-inline-start
text-align: left→text-align: start
width / height→inline-size / block-size

Note: the English captions are marked dir="ltr" so they read correctly even in right-to-left mode. Blanket-flipping a container to RTL leaves neutral characters like periods resolving against the RTL context and jumping sides — which is exactly why real sites set direction per the content's language rather than flipping everything at once.
