Common UI patterns, natively

How far the platform has come on the things people used to reach for a JavaScript library to build. The real lesson is the spectrum — some are fully solved, some need a line of JS, one isn't there yet. Being honest about which is which is the point.

Accordion native · 0 JS

Stacked <details> elements. Give them a shared name and only one opens at a time — the browser enforces it. Keyboard and screen-reader support are built in.

How do I pay my utility bill?
Pay online with a card or bank account, or in person at City Hall, 1 Emerald Plaza.
When is trash collected?
Collection day depends on your district — look it up by address on the Services page.
How do I report a loose brick?
Submit a service request for the Yellow Brick Road and we'll dispatch a crew.
<details name="faq"><summary>…</summary> … </details> /* shared name = only one open at a time, no JS */

Modal native element · you drive it with JS

The <dialog> element gives you the dimmed ::backdrop, focus trapping, Escape-to-close, and top-layer stacking (no z-index wars) for free — richer than a popover. You drive it with a little JS: .showModal() to open, .close() to close. One real gotcha: clicking the backdrop does not close it by default — add the newer closedby="any" attribute (or a one-line listener) for click-outside dismiss.

<dialog id="dlg" closedby="any">…</dialog> /* click-outside closes (newer attribute) */ dlg.showModal() // open dlg.close() // close /* free: ::backdrop, focus trap, Esc, top layer. NOT free: backdrop-click (closedby, or a JS line) */ /* zero-JS close alternative: put buttons in <form method="dialog"> */

Popover native · 0 JS

For lighter overlays — menus, tips, non-modal panels — the popover attribute opens and closes with zero JavaScript, wired up by popovertarget. Also uses the top layer, also light-dismisses (click outside / Escape).

City Hall is open Monday–Friday, 8 a.m.–5 p.m. Closed weekends and holidays.

<button popovertarget="tip">Show office hours</button> <div id="tip" popover>…</div> /* opens, closes, light-dismisses — no JavaScript at all */

Tabs not solved in pure CSS

You can switch panels with hidden radios + :checked (below, and it works visually) — but it is not accessible, which disqualifies it for real use.

Permits, utility bills, trash pickup, and park reservations.
Licenses, bids & RFPs, and zoning information.
Maps, event calendar, and the Emerald Festival schedule.
Why this is a cautionary demo, not a recommendation: real tabs need arrow-key navigation, the tablist/tab/tabpanel ARIA roles, and managed focus — none of which the CSS-only version provides. It looks like tabs but doesn't behave like tabs for keyboard and screen-reader users. Tabs still need real JavaScript (or a vetted component) to be accessible. There's a native tabs proposal in progress, but it isn't here yet.
The spectrum: accordion = fully native · modal = native element + 1 line · popover = fully native · tabs = still needs JS. Honest beat for the talk: CSS caught up on a lot — not everything. Say which is which.
