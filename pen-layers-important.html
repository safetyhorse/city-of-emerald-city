Cascade layers & the !important escape hatch

Purple = a rule in the framework layer won; green = the overrides layer won. Order is declared once: @layer framework, overrides; — so for normal rules, overrides (later) always wins, however specific the framework selector is.

Case 1
Layers beat specificity. The framework rule has four selectors (body #main .panel .swatch); overrides is one plain .case1. The plain class still wins — it's in a later layer. This is why you no longer reach for !important to win a specificity fight.
Case 2
But !important escapes the layers. The framework layer marked its rule !important, so it wins even though overrides is the later layer — the !important jumps to a higher tier the layer order can't reach. Delete the !important in DevTools and watch Case 2 turn green: the only cure is removing it. You can't out-layer it.
